MBosch · Production ML

Predictive maintenance

Autoencoder anomaly detection on 40+ TB of sensor telemetry

I owned the anomaly-detection model end to end (data, training and production), and testing cycles got 4 months shorter, saving an estimated €300K+ a year.

Problem
Endurance tests run continuously for about six months, and failures typically appear only after two to three months, when a component fails or drifts outside its expected intervals. Catching that late meant long cycles and damaged parts.
What I owned
The model end to end: data handling and batch preprocessing of 40+ TB of high-frequency telemetry on Databricks/PySpark, training and validating the autoencoder, and running real-time detection in production.
Result
Testing cycles shortened by 4 months, with an estimated €300K+ in annualized savings; per-partition processing time cut by over 50%.
Key decision
An autoencoder that learns what a normal 12-second measurement window looks like, so one model covers hundreds of components and 100+ ECUs.
Implementation & evaluation details
Why an autoencoder
Whether a measurement is anomalous is judged over a 12-second window, across hundreds of components and 100+ ECUs. An autoencoder learns what those 12 seconds should look like and flags any window that doesn’t match. One approach scales across every component, rather than a separate rule or model for each.
How it’s measured
€300K+ is an annualized estimate, from reduced test-bench downtime and fewer components damaged thanks to earlier detection. The model was validated on separate validation and test sets of measurements supplied by the hardware team before rollout.

GBosch · Applied GenAI

Valfred: GenAI data assistant

Natural-language queries over Bosch testing platforms

I orchestrated the multi-agent assistant and deployed it on Databricks; for about 30 beta users, a 10–15 minute data lookup became a 1–2 minute question.

Problem
Finding data in Bosch’s LEEPA/WebDVP testing platforms took engineers 10–15 minutes of manual lookup per question.
What I owned
Orchestrated a multi-agent assistant with optional vector schema retrieval and self-healing SQL agents, deployed via MLflow and Unity Catalog on Databricks. Used by the hardware team in my department to pull measurement details from tests. About 30 users, in beta when I left.
Result
A 10–15-minute manual lookup became a natural-language request answered in about 1–2 minutes, most of it data retrieval, not the agent. On ~500 internal test queries: 65% answered correctly on the first pass, ~81% within three attempts.
Key decision
Self-healing SQL: a query that fails is repaired from its own error message, with up to two retries before the error is reported.
Implementation & evaluation details
Schema in the prompt
By default the whole schema goes into the prompt. A vector mode sends only the columns closest to the question, shrinking the schema text about 4× in local tests and keeping prompts manageable as schemas grow. The trade-off: it can leave out a table the query needs.
Self-healing
When generated SQL fails to execute, a repair step sends the failing query and its error back to the model and runs the rewrite; after two retries (three attempts) it stops and reports the error to the user.
How it’s measured
About 500 internal test queries, built with the hardware and data teams and each checked for correctness. 65% were answered correctly on the first pass; self-healing recovered 45% of the remaining 35%, for ~81% overall.

APersonal project · End to end

ASL Guide

ASL learning platform: recognition, translation, practice

I built the whole platform end to end (recognition, translation and practice), reaching 95.5% classifier accuracy on a held-out split.

Why I built it
A left-handed user signed to my model and it failed: I’d built for an imaginary user. Afterwards I mirrored landmarks during training and gathered data from left-handed signers.
What I built
A full-stack platform: in-browser fingerspelling recognition (MediaPipe + TensorFlow.js), a two-agent Gemini 2.5 Flash pipeline in LangGraph that applies 11 documented ASL grammar rules for English → ASL translation, and a Duolingo-style course of 100 signs over 10 levels with SM-2 spaced repetition.
Result
95.5% classifier accuracy across 36 fingerspelling classes, with in-browser inference under 100 ms; Gemini context caching cut per-request input tokens by ~73%.
Key decision
Classification runs in the browser, so camera frames never leave the user’s device and recognition doesn’t wait on a server; the server is only used for translation.
Limitations
A study aid, not a substitute for fluent signers. The hosted demo is currently offline; the source is on GitHub.
Evaluation details
How it’s measured
95.5% is accuracy on a held-out split of Kaggle’s ASL alphabet & numbers dataset, stratified by sign class. The dataset’s frames carry no signer labels, so this isn’t a signer-independent result.
